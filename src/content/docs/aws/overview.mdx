An installation of Spinbox lives in one AWS account and one region. It is created by one OpenTofu
module, [spin-terraform-aws](https://github.com/spin-stack/spin-terraform-aws):

```hcl
module "spin" {
  source       = "github.com/spin-stack/spin-terraform-aws?ref=v20261024.01"
  spin_version = "v20261019.02"
  domain       = "spin.example.com"
}
```

Pin `ref` to one of the module's tags, which are dated like Spinbox's releases
(`v<YYYYMMDD>.<N>`), so that the module changes only when you move it.

## What it creates

- **A VPC** of its own, with public subnets and no NAT gateway. The bucket is reached through the
  free S3 gateway endpoint.
- **The control plane**, on one machine ([`instance_type`](/reference/terraform/controlplane/#instance_type)), in an autoscaling group of one. It also
  runs the installation's PostgreSQL 18 and its log and metric stores.
- **The proxy**, on one machine ([`proxy_instance_type`](/reference/terraform/controlplane/#proxy_instance_type)) with an elastic IP, in an autoscaling group of one.
- **The runners**, an autoscaling group of large spot machines with local NVMe ([`instance_types`](/reference/terraform/runners/#instance_types)), which
  the control plane sizes from zero.
- **S3 buckets, each with one owner**: the volumes, with versioning and Object Lock; the
  database's archive, under Object Lock too; logs, traces and metric backups; the proxy's
  certificates; and what each machine starts from.
- **Two Route 53 zones**: your domain's public zone, and a private zone (`spin.internal`) the
  machines find each other by.
- **The installation's secrets**: its CA and the first administrator's password in SSM Parameter
  Store, and its encryption, volume and identity keys in KMS.
- **IAM roles** for each machine, all under one permissions boundary.
- **A VPC flow log**, kept in CloudWatch for <Value name="logRetentionDays" />.

Every machine boots **Spin OS**, the image published for the release, in the regions [Spin OS images](/reference/terraform/images/) lists.

## The choices it makes

These are made for you, and each one has a reason:

| Choice | Why |
|---|---|
| Every machine is replaced to update, never patched | Its root filesystem is read-only and verified; a machine runs exactly what the release signed. |
| The proxy is the only machine the internet reaches | The control plane, the runners and the database take no connection from outside the VPC. |
| No SSH on any machine | A shell is AWS Session Manager, decided by IAM and logged by AWS. |
| No NAT gateway | It would cost more than the machines that run all the time. |
| Runners are spot and start from zero | They are the largest cost, and they only cost while a workspace runs. |
| Runners join by their IAM role | There is no join token to create, store, rotate or leak. |
| No role can grant itself more | A permissions boundary on every role denies IAM writes, parameter writes, and lifting the bucket's lock. |
| Telemetry stays in the installation | Logs, traces and metrics are kept on the control plane's machine, over the logs bucket. |
