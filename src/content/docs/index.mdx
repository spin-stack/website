## What it looks like

```bash
spin workspace create --name demo --wait
spin snapshot create demo --description clean --with-memory --wait
spin exec demo -- sh -c 'echo hello > /etc/greeting; rm /etc/issue'
spin snapshot create demo --description after --wait
spin snapshot diff demo <after-id> --from <clean-id> --under /etc
spin workspace restore demo <clean-id> --with-memory
spin workspace delete demo
```

<Output name="diff.txt" caption="spin snapshot diff demo <after-id> --from <clean-id> --under /etc" />

A workspace is [a KVM virtual machine](<feature:A machine per workspace: KVM, its own kernel, root, a persistent disk, SSH>) with its own kernel, a persistent disk and root. The diff
runs in a separate machine and [lists every file added, removed or modified](<feature:A diff of the files that changed between two snapshots>) between two snapshots.
A restore from [a memory snapshot](<feature:Snapshots with memory, resumed with their processes>) puts the processes back as they were.

## Straight answers

- **AWS only.** One OpenTofu module installs Spinbox in your account. There is no hosted version.
- **x86-64 only.** Runners are x86-64 machines with nested virtualization.
- **Linux guests only.** A workspace boots the kernel Spinbox provides.
- **No GPUs.** There is no way to ask for a runner of a particular kind.
- **One region, one control plane.** An installation lives in one AWS region.

Each answer is a limit row of the [status page](/reference/status/), held to the code by a test.
