# Spinbox documentation

The documentation of [Spinbox](https://github.com/spin-stack/spin), at
<https://spin-stack.github.io/website/>, built with [Astro Starlight](https://starlight.astro.build)
and published to GitHub Pages.

The rule this site keeps: a page is generated from the code it describes, or held to it by a
check that fails the build, or it does not exist. Everything below is one of those checks.

```
go tool task install      # dependencies, through Socket Firewall (go tool sfw)
go tool task dev          # http://localhost:4321, live reload
go tool task gate         # what CI runs: the gates, the install, the tests, the public reference, the build, every link
go tool task check        # the gate, and the reference against the sources
go tool task exposure     # what this public repository shows: every ref, its PRs and issues
go tool task --list       # everything else
```

Task is a tool in `go.mod`, so `go tool task` is the version CI runs; the tasks below are named
without it. `task gate` is what CI runs, its one step: it fails first on an install that skips
the firewall (`go tool sfw check`) or a workflow step that is not one task (`go tool taskgate`),
and `task check` is that and more: CI cannot read spin while it is private, so the reference is
checked against checkouts of spin, spin-terraform-aws and brand beside this one (`SPIN=`,
`TERRAFORM=`, `BRAND=` to point elsewhere). The half that needs no spin is in the gate:
`task reference:public` fetches spin-terraform-aws and brand into `.sources/`, at the commits
`src/data/reference.json` records, and runs `refgen -only terraform,brand -check`, which builds
no CLI and keeps what the site says of spin as `reference.json` has it.

- **The repository is public**, and so is every pull request the moment it is opened.
  `task exposure` (`go tool exposure`) reads every ref's commits, pull request heads included,
  and the issues, pull requests and comments for secrets and for what is private without being one;
  `.github/workflows/exposure.yml` runs it every morning. A value public on purpose is answered in
  `.github/exposure-allow.txt` with why, a secret gitleaks takes for one in `.gitleaks.toml`.
- **Pages** are Markdown under `src/content/docs/`. Every page needs a `description`: it is its
  line in `llms.txt`. A page must be in `src/lib/nav.mjs`, or the build fails. Each group there
  belongs to a topic - Docs, Install and operate, Security, Reference - and the sidebar shows one
  topic's groups at a time (`starlight-sidebar-topics`). Images and diagrams zoom in place
  (`starlight-image-zoom`), and every page title offers its Markdown twin, copied or opened.
- **Reference pages** under `src/content/docs/reference/` are generated by `task reference` from
  checkouts of spin and spin-terraform-aws beside this one (`SPIN=`, `TERRAFORM=` to point
  elsewhere). Each names its source in its frontmatter (`source: repository:path`), and its footer
  links that source at the documented commit instead of an edit link. Edit the source, not the
  page. Every page's footer says which spin release an installation runs, and the tree the
  reference is generated from.
- **Prose held to spin's own lists**: a page's description is one line of at most 160
  characters (it is its line in `llms.txt`), every `SPIN_` variable a page names is one spin's
  `hack/env-catalog.txt` lists, and the table of states in `concepts/workspaces.md` is the API's
  `WorkspaceState`, both ways. `task reference:check` fails on each.
- **What the site documents** is `src/data/reference.json`, written by `task reference`. Two
  things it keeps apart: the spin release an installation runs (`spin.installs`, the newest
  release `images.json` has images of), and the spin commit the reference is generated from
  (`spin.commit`, with `spin.tag` empty when no release is cut from it, so the site says
  "generated from spin main at <commit>, not released"). With them, the commits of
  spin-terraform-aws and brand, and the feature board's counts, which the landing page shows.
  Every release a hand-written page names is pinned to the one an installation runs:
  `task reference` rewrites it, and `task reference:check` fails on another.
- **The status page** `reference/status/` is written from `spin features`, the feature board a
  test in spin holds to the tree. A built row shows what says it exists, and the tests that check
  it end to end or what none checks yet (`endToEnd`, `endToEndGap`); the landing page counts the
  first. refgen fails on a field of the board it does not know, on a built row with both or
  neither, and on a test spin does not have. The bullets of `overview/limitations.md` are its limit rows,
  and `task reference:check` fails on a bullet that is not one, or a row no bullet leads with.
  The landing page's straight answers are limit rows too, and the check fails on one that is not.
- **What a page says Spinbox does** is a link to the feature board's row that says so:
  `[idle suspend](<feature:Idle suspend, with a question before it that a keep answers>)`. The
  build points it at the row's area on the status page (`src/lib/feature-links.mjs`) and fails on
  a row the board does not have; `task reference:check` also fails on a row that is not built.
  The board is `src/data/features.json`, written by `task reference`.
- **Commands on the other pages** are held to the same checkouts: every `spin` command in a
  shell block must be one the CLI has, with flags its help lists, and every `task` one spin's
  Taskfile has (after a `cd` into another checkout, that one's). `task reference:check` fails
  on one that is not.
- **Diagrams** are the ones spin and spin-terraform-aws draw beside their sources (`.dot`, `.d2`):
  `task reference` copies each into `src/assets/diagrams` and writes its words to
  `src/data/figures.json`, which a Markdown twin carries in the picture's place. The site draws
  none of its own. `<Figure name="…" caption="…" />` shows one.
- **For models**, the build writes `llms.txt` (every page, with its description),
  `llms-full.txt` (every page's Markdown) and a `.md` twin of each page, all from the same
  content (`src/pages/`). The build fails on a twin that still carries MDX: a component, an
  expression or a directive `src/lib/pages.ts` does not translate.
- **The look** is spin-stack/brand's: its palette, checked there for contrast and perceptual
  distance on real panels and through colour-vision deficiencies, and the organization's mark.
  `task reference` copies them from a checkout beside this one (`BRAND=` to point elsewhere) into
  `src/styles/brand-*.css`, `src/assets/` and `public/`, with the app's screenshots, and
  `task reference:check` fails on a copy that is not brand's, on screenshots of another release
  than installations run, and on one whose test spin no longer has; `src/styles/custom.css` says only how the site's parts use them.
  IBM Plex is served from the site, and a hero draws a workspace's disk as its layers, worked
  step by step (`src/components/Hero.astro`, `Disk.astro`). `task links` fails a page that loads a
  script, a stylesheet, a font or an image from another site.
- The site is served at `SITE_URL` + `BASE_PATH`, by default `https://spin-stack.github.io` and
  `/website` (a GitHub project page). Content links from the root (`/concepts/network/`) and the
  build puts the base in front; `task links` fails on one it cannot resolve.
- **Links out of the site** are opened by `task links:external`, with no credential, as a reader
  would: every link to another site and every `ghcr.io` reference a page quotes. A page links
  only to spin-stack repositories a reader can open (`publicRepos` in `tools/refgen`).
- Pushing to `main` builds and publishes to GitHub Pages (`.github/workflows/pages.yml`).

## Contributing

Pull requests are welcome. One from a fork runs the Gate once a maintainer approves it, and never
deploys: only `main` publishes. Dependencies are locked and installed through [Socket Firewall](https://spin-stack.github.io/go-tools/sfw/),
which `go tool sfw check` holds every install and every workflow to; `pnpm-workspace.yaml` names the few that
may run an install script, and a release must be a week old before it is taken.

A security problem in Spinbox goes to a private advisory, never an issue: see
[Reporting a vulnerability](https://spin-stack.github.io/website/security/reporting/).
