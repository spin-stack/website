# Spin documentation

The documentation of [Spin](https://github.com/spin-stack/spin), at
<https://spin-stack.github.io/website/>, built with [Astro Starlight](https://starlight.astro.build)
and published to GitHub Pages.

The rule this site keeps: a page is generated from the code it describes, or held to it by a
check that fails the build, or it does not exist. Everything below is one of those checks.

```
task install      # dependencies
task dev          # http://localhost:4321, live reload
task check        # the reference against the sources, the build, and every link
task --list       # everything else
```

`task check` is what CI runs and more: CI cannot read spin while it is private, so the reference
is checked against checkouts of spin and spin-terraform-aws beside this one (`SPIN=`,
`TERRAFORM=` to point elsewhere).

- **Pages** are Markdown under `src/content/docs/`. Every page needs a `description`: it is its
  line in `llms.txt`. A page must be in `src/lib/nav.mjs`, or the build fails.
- **Reference pages** under `src/content/docs/reference/` are generated by `task reference` from
  checkouts of spin and spin-terraform-aws beside this one (`SPIN=`, `TERRAFORM=` to point
  elsewhere). Edit the source they name, not the page.
- **Prose held to spin's own lists**: a page's description is one line of at most 160
  characters (it is its line in `llms.txt`), every `SPIN_` variable a page names is one spin's
  `hack/env-catalog.txt` lists, and the table of states in `concepts/workspaces.md` is the API's
  `WorkspaceState`, both ways. `task reference:check` fails on each.
- **What the site documents** is `src/data/reference.json`, written by `task reference`: the spin
  release an installation runs, the commits the reference was generated from, and the feature
  board's counts, which the landing page shows. Every release a hand-written page names is pinned
  to that release: `task reference` rewrites it, and `task reference:check` fails on another.
- **The status page** `reference/status/` is written from `spin features`, the feature board a
  test in spin holds to the tree. The bullets of `overview/limitations.md` are its limit rows,
  and `task reference:check` fails on a bullet that is not one, or a row no bullet leads with.
  The landing page's straight answers are limit rows too, and the check fails on one that is not.
- **What a page says Spin does** is a link to the feature board's row that says so:
  `[idle suspend](<feature:Idle suspend, with a question before it that a keep answers>)`. The
  build points it at the row's area on the status page (`src/lib/feature-links.mjs`) and fails on
  a row the board does not have; `task reference:check` also fails on a row that is not built.
  The board is `src/data/features.json`, written by `task reference`.
- **Commands on the other pages** are held to the same checkouts: every `spin` command in a
  shell block must be one the CLI has, with flags its help lists, and every `task` one spin's
  Taskfile has (after a `cd` into another checkout, that one's). `task reference:check` fails
  on one that is not.
- **For models**, the build writes `llms.txt` (every page, with its description),
  `llms-full.txt` (every page's Markdown) and a `.md` twin of each page, all from the same
  content (`src/pages/`). The build fails on a twin that still carries MDX: a component, an
  expression or a directive `src/lib/pages.ts` does not translate.
- **The look** is Spin's own: the spin-stack mark's colors and IBM Plex, served from the site
  (`src/styles/custom.css`), and a hero that draws a workspace's disk as its layers
  (`src/components/Hero.astro`, `LayerStack.astro`). `task links` fails a page that loads a script,
  a stylesheet, a font or an image from another site.
- The site is served at `SITE_URL` + `BASE_PATH`, by default `https://spin-stack.github.io` and
  `/website` (a GitHub project page). Content links from the root (`/concepts/network/`) and the
  build puts the base in front; `task links` fails on one it cannot resolve.
- **Links out of the site** are opened by `task links:external`, with no credential, as a reader
  would: every link to another site and every `ghcr.io` reference a page quotes. A page links
  only to spin-stack repositories a reader can open (`publicRepos` in `tools/refgen`).
- Pushing to `main` builds and publishes to GitHub Pages (`.github/workflows/pages.yml`).

## Contributing

Pull requests are welcome. One from a fork runs the Gate once a maintainer approves it, and never
deploys: only `main` publishes. Dependencies are locked; `pnpm-workspace.yaml` names the few that
may run an install script, and a release must be a week old before it is taken.

A security problem in Spin goes to a private advisory, never an issue: see
[Reporting a vulnerability](https://spin-stack.github.io/website/security/reporting/).
